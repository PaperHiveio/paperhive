# paperhive.yml (plugin)

Every Hive plugin jar has a `paperhive.yml` at its root. It plays the role a `plugin.yml` plays for Bukkit plugins;
a Hive plugin doesn't need a `plugin.yml`.

```yaml
name: MyPlugin
version: 1.0.0
description: Network-wide announcements
main: com.example.myplugin.MyPluginHivePlugin
# the server half: every server the plugin is enabled for loads it
server-main: com.example.myplugin.MyPluginServerPlugin
```

| Key | Required | |
|---|---|---|
| `name` | yes | The plugin's name: in logs, `plugin` commands and `DisabledHivePlugins`. Unique in the hive. |
| `version` | yes | Its version. |
| `main` | yes | The [host half](../plugins/host-half.md): a class extending `PaperhivePlugin`. |
| `description` | no | One line about it. |
| `server-main` | no | The [server half](../plugins/server-half.md): a class extending `HiveBukkitPlugin`. Leave it out for a host-only plugin. |

Paperhive checks the file when it loads the jar: a missing required key, or a `server-main` class that isn't in the
jar, is reported and the plugin is skipped.

## Generated by the Gradle plugin

With the [Gradle plugin](../plugins/gradle-plugin.md), you can leave this file out and set the same values in
`build.gradle.kts`:

```kotlin
paperhive {
    main = "com.example.myplugin.MyPluginHivePlugin"
    serverMain = "com.example.myplugin.MyPluginServerPlugin"
    pluginDescription = "Network-wide announcements"
    // name and version default to the project's
}
```
